# dpr v0.2: accuracy against an LLM audit of a private repository

Source: comparison of dpr v0.1.0 against the audit-prep-assistant audit of a private comparison repository
(2026-09-23, kept outside the repository). v0.1.0 matched 8, partly matched 9 and missed 30
of the 47 Critical, High and Medium audit findings, and about 95% of its 1589 findings were
false positives.

Goal: option 1 (cut the noise), then option 2 (close the gaps), then rescan the comparison repository and
compare again. Business-logic and out-of-repo findings (F-09, F-13, F-16 to F-19, F-22, F-35,
F-48, F-49, F-51, F-53) stay out of scope.

Rules for every package: test first, positive and negative fixtures, spec updated
(`docs/superpowers/specs/2026-09-16-dpr-design.md`, section 3 refinements and the rule tables),
`uv run pytest`, `ruff check --no-fix` and `ruff format --check` clean, one commit per package.
No network, no secret values in output, the comparison repository is read-only.

## Phase 1: noise

- [x] WP1 Scan scope. In a git repository, scan tracked files only (`--include-untracked`
      adds untracked files that git does not ignore). Call a data file "committed" only when
      git tracks it. Detect vendored and minified libraries (known library names, `*.min.js`,
      bundle banners, `djangojs/`-style vendored apps, collected static folders) and report
      each once as a dependency issue instead of running sink rules on them.
- [x] WP2 Precision. `OWASP-A01-PATH-TRAVERSAL` fires only on `open()`, `os.path.join()`,
      `pathlib` joins or `storage.save()` fed by a request value, never on Django
      `form.save()`. CONFIRMED only when the flow is read end to end. `BASE-DEBUG-ON` and
      `BASE-WEAK-HASH` skip test and CI settings modules. Drop the weak
      `OWASP-A02-WEAK-RANDOM-TOKEN` name-only match on identifiers.

## Phase 2: gaps

- [x] WP3 Access control. Resolve custom auth decorators one level (`login_required(
      user_passes_test(...))` wrappers). Map URL names to view functions, never to a Celery task
      of the same name. `OWASP-A01-UNSCOPED-QUERY`: taint `request.GET/POST/data` and body IDs,
      handle DRF `@api_view`, treat `filter_by_user()`-style managers as scoping, lower role-gated
      staff routes, fold `OWASP-A01-GUESSABLE-ID` into it. New rule `OWASP-A01-PUBLIC-SENSITIVE`:
      a public route that sets a password or saves a user, queries personal data by a request
      value, returns a file or PDF, or starts a background job.
- [x] WP4 Secrets and settings. Literal defaults for secret-named env reads, the `SECRET_KEY`
      fallback, `PickleSerializer` sessions, literal `auth=` credentials, `DEBUG` that defaults on,
      `WAFFLE_SWITCH_DEFAULT = True`, an environment flag that defaults to production. Detect
      django-axes as a lockout limiter.
- [x] WP5 Django and deploy rule pack. Open redirect, `csrf_exempt` plus `SameSite=None`, GET
      handlers with side effects, oversized upload limits and unvalidated file fields, forms that
      expose `is_superuser`/`is_staff`/`groups`, `random` output reaching `set_password`, plain
      `http://` outbound calls and passwords in URL query strings, outbound calls with no timeout,
      end-of-life framework versions from a bundled table, Dockerfile with no `USER`,
      world-writable `chmod`, and a thin `.dockerignore`.
- [x] WP6 Value-based personal data. Find South African ID numbers (Luhn-valid, date-valid) and
      bank-account-shaped values in tracked data files with no header row and in literals in
      code and migrations. Report where, never the value.
- [x] WP7 Gap sweep. Close the remaining audit misses with general rules: public
      routes that list stored records (F-01) or return records reached from a request id (F-08
      `cat22_file`), list endpoints that return every user or personal record to any signed-in
      caller (F-06), public test routes that raise on demand (F-42), request loggers that store
      whole headers or bodies (F-31), request tokens compared with `==` (F-34), and form choices
      of a role template that carries `is_superuser` (F-15). Cut noise: role-gated
      `OWASP-A01-UNSCOPED-QUERY` findings form one register issue per app and one grouped entry
      in the report, and `OWASP-A04-GET-SIDE-EFFECT` no longer counts `dict.update` in a loop.
      Not changed, with the reason:
      - F-08 `/get/generate_payat_number`: the handler and its model helper only read (a random
        unassigned number); the "uses up a number" claim is not visible in code, so no
        deterministic rule can flag it without flagging every public read.
      - F-44: the auth user's email is `unique=True`, so `AUTH-EMAIL-NOT-UNIQUE` is right not to
        fire; the real defect is `.filter` on `None` in the `MultipleObjectsReturned` branch, a
        crash bug outside what dpr checks.
      - F-34 (rest): the `None` check after use is a crash bug, not a data protection pattern, and
        plain-text login tokens need a login-token flow detector (`AUTH-TOKEN-PLAINTEXT` stays
        scoped to reset and verification flows); only the `!=` token compare is a rule.
- [x] WP8 Precision round 2. `OWASP-A01-UNSCOPED-QUERY`: an ownership or tenant check on the
      caller after the load scopes the lookup on any route, handlers whose every response
      carries no personal data and existence or count lookups are skipped, role-gated lookups
      by a tenant id (brokerage, company, branch, organisation, account, agency) stay medium
      (F-33), and routes that `OWASP-A01-PUBLIC-SENSITIVE` or `OWASP-A01-UNSIGNED-CALLBACK`
      report carry the lookup there instead of a second finding. `OWASP-A06-VENDORED-LIB`: one
      finding per library with every copy, never a documentation folder, versions from
      constants such as `pdfjsVersion`. Small false positives: a Django signing salt,
      mixed content in vendored HTML, a script printing its operator's own input, reset token
      links and done pages as public forms, header findings citing test or vendored settings.
- [x] WP9 Precision round 3 and advisories. `OWASP-A01-UNSCOPED-QUERY`: a back-office admin gate
      (superuser, staff, a permission for administering the tenant) sends a tenant lookup to the
      low role-gated group while a member-level permission keeps it medium (F-33); a queryset
      narrowed to the caller in a branch, through a name derived from `request.user`, scopes
      later lookups on it; responses built only from prices, premiums, plan or product fields,
      or from records of a model with no personal fields, are quiet; provider delivery and
      status routes are `OWASP-A01-UNSIGNED-CALLBACK`, also when they start a background job;
      role-gated lows become one finding per app root that lists every route. New rule
      `OWASP-A06-KNOWN-ADVISORY` from a small, dated, offline table `data/advisories.yaml`
      matched against pinned Python and npm versions and vendored library versions.

- [x] WP10 Precision on a JS/TS and FastAPI repository. A second private repository (Express
      with Prisma, a FastAPI AI service, Docker compose) gave 73 Critical and High findings, of
      which 1 was real. Fix the general causes:
      - `OWASP-A03-RAW-SQL`: a `$queryRawUnsafe`/`$executeRawUnsafe` call that passes values as
        extra arguments is not an injection when every `${...}` is a module constant, a string
        literal, or a same-file helper that returns only literal or placeholder text. Report
        what is left at medium INFERRED, and scripts no route reaches at low.
      - `OWASP-A03-XSS-SINK`: `Markup()` over an f-string whose fields are numeric formats, or
        over `Markup.escape()`/`escape()` output, is safe.
      - `LEAK-HARDCODED-KEY`: skip test files and scripts named `test-*`, `test_*`, `*_test.*`
        or `*.test.*` in any folder, and key-shaped values in comments that hold a placeholder
        word.
      - `BASE-DOCKERIGNORE-THIN`: use the `.dockerignore` of the build context (the compose
        `build.context`, else the Dockerfile folder). A multi-stage build whose final stage copies
        only from earlier stages or named build output ships nothing from the context.
      - `BASE-DOCKER-ROOT`: a Dockerfile used only by a dev compose file or named `*.dev` is low;
        a stock `nginx` base with no `USER` is skipped (workers drop to `nginx`).
      - `LEAK-ENV-IN-HISTORY`: a historic `.env.test`, `.env.example` or `.env.sample` is low.
      - `ABUSE-PAID-UNAUTH` and `OWASP-A01-PUBLIC-SENSITIVE`: FastAPI `dependencies=[Depends(x)]`
        on `include_router`, `APIRouter(...)` or `FastAPI(...)` counts as a gate when `x` checks
        a token, key or user. An internal-token gate turns paid findings on that service into one
        low finding when the token check does nothing if its env value is unset.
      - `ABUSE-PAID-UNLIMITED`: skip routes of a service gated by an internal token; the limit
        belongs to the calling routes, which keep their own findings where the call is traced.
      - `OWASP-A01-PUBLIC-SENSITIVE`: an LLM SDK call (`messages.create`, `chat.completions.create`)
        is not a back-office write, and a route that renders a file only from the request body
        and reads no stored record is not "returns a file".
      Rescan both private repositories before and after; no earlier true finding may be lost.

- [x] WP11 Internal service trace. Follow a JS/TS route handler (one or two calls deep, across
      relative imports) to an outbound `fetch`/`axios` call whose URL is built from an env value
      or a constant that names another service in the repository, and map the URL path to that
      service's route (FastAPI, Flask or Express). When the target route reaches a paid SDK and
      the calling route has no limiter or credit check, report `ABUSE-PAID-UNLIMITED` on the
      calling route, naming the internal route it calls. Calling routes with a limiter stay quiet.
